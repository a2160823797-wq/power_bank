## 使用

页面统一使用中文，电池监测、数字电位器、异常记录与固件升级均显示中文文案。

1. 使用桌面版 Chrome 或 Edge，连接 USB 转串口和目标设备。
2. 双击 `PowerBank.html` 打开页面。运行现成页面无需安装 Node.js 或启动本地服务。
   首次授权需手动选择设备；连接成功后会记住设备标识，下次打开自动尝试连接。使用同一浏览器并保持网页路径不变，才能复用此前授权和本地记录。两页共用一份设备记忆，刷新或再次打开时校验并自动连接此前记住的设备。
3. 页面记住最后打开的功能，首次默认进入“电池监测”。点击“连接设备”接收下位机上报；升级时切换到“固件升级”，选择目标设备对应的 APP `.bin` 固件，点击“一键升级”。用户无需选择芯片型号或填写升级参数。
4. 点击“一键升级”后，在浏览器弹窗中选择目标串口；已有监测连接时也需要选择。页面不再提供升级连接选项。电池监测和数字电位器已授权设备可通过上述识别流程自动连接。
5. 等待自动升级完成；需要中止时点击“取消”。

升级过程中显示当前状态和传输进度，失败时可展开查看详情。升级要求目标 MCU 使用支持本工程 CMD 0/2/3 和 YMODEM 的配套固件；芯片型号本身不能保证协议兼容，厂家 ROM ISP 协议需要另行适配。升级期间锁定固件选择。

## 开发与验证

本工程只包含上位机。所有升级固定使用 IAP + YMODEM、1500000 baud、8N1 和 1K（1024 字节）固件数据包。用户页面仅保留固件选择、升级状态及操作按钮，不展示连接方式、型号、内存地址、容量、协议、串口参数、超时或重试配置。`DEFAULT_CONFIG` 只包含统一传输参数：5000 ms 响应超时、30000 ms 握手超时、最多尝试10次。型号偏好存储已删除，旧浏览器记录中的型号和自定义参数不再读取。

上位机仅检查文件非空和原始固件长度可由 32 位字段表达，将 BIN 作为原始字节传输。应用写入地址、Flash/RAM 容量、CPU 架构、镜像合法性和启动条件均由各 MCU 的 Bootloader 判断；Cortex-M 设备在设备端检查向量表，其他架构按自身启动格式检查。新增 MCU 只需实现下述固件协议，无需在上位机新增型号或内存配置。用户仍需选择目标产品对应的固件，当前长度和 CRC32 信息不包含产品型号，上位机无法据此判断固件是否属于该产品。

参考工程 `x202_015` 的当前 CS32L015 Bootloader 支持同一命令协议和 STX 1024 字节接收，UART 缓冲为 1030 字节。设备在 CMD 3 阶段拒绝过小或超应用区容量的长度，写入完成后检查实际长度、CRC32 和向量表并决定是否允许启动；上位机不再保存这颗芯片的 APP/RAM 参数。删除主机向量表检查后，非法向量固件由设备在写入完成时拒绝，此时原 APP 已擦除。统一响应超时保持 5000 ms，以便在该工程 7000 ms 最终 ACK 重答窗口内重试。

当前参考工程 `C:/Desktop/prj/hand_fan/hand_fan_910/iap/src/xymodem.c` 的 CW32L910 接收缓冲只容纳 128 字节数据包，且 `xymodem_read()` 收到 STX 会发 CAN 拒绝，因此这版 Bootloader 仍需更新为支持 1K 才能接入统一上位机。本次未修改任何 MCU 工程。

### IAP 升级流程

1. 检查 BIN 非空和长度范围；校验失败即停止升级。
2. CMD 0 确认设备在线。
3. CMD 2 自动进入升级状态，等待设备发出 `C`。
4. CMD 3 发送原始固件长度和 CRC32，等待设备接受。
5. 发送 YMODEM 文件头、固定 1K 数据包、EOT 和结束空包，收到最终 ACK 后报告传输成功。EOT 收到 NAK 时再次发送，收到 ACK 后等待 `C` 并发送结束空包。文件头和结束空包使用 SOH + 128 字节，固件数据包使用 STX + 1024 字节；末包用 `0x1A` 补齐，原始固件长度和 CRC32 不包含填充。

命令帧格式为 `AA 55 | CMD[1] | LEN[2] | DATA[LEN] | CRC8[1]`，长度为小端 uint16。CRC8 覆盖命令、长度和数据，初值 `0xFF`，多项式 `0x07`。CMD 3 数据为原始固件长度 LE32 和 CRC32 LE32。

YMODEM 包格式为 `SOH/STX | 包序号 | 序号按位取反 | 数据 | CRC16高字节 | CRC16低字节`，数据包序号从 `1` 开始，按 8 位回绕。CRC16 覆盖整包数据区，包括末包填充，初值 `0`，多项式 `0x1021`。文件头序号为 `0`，128 字节数据区包含 ASCII 文件名、零分隔符、十进制原始文件长度和零终止符。结束空包同样为序号 `0` 的 SOH 包，128 字节数据区全零。

CMD 3 的 CRC32 只覆盖原始固件，使用反射多项式 `0xEDB88320`，初值和最终异或均为 `0xFFFFFFFF`；以小端 32 位值发送。设备应将文件头中的长度与 CMD 3 的长度核对，实际写入末包时裁掉填充。

运行中的 APP 必须支持 CMD 0 在线确认和 CMD 2 进入升级状态；Bootloader 必须支持 CMD 0、CMD 2、CMD 3 及 YMODEM 1K 接收。仅实现 YMODEM 接收器不足以自动进入升级。在线和命令接受回复首个数据字节为 `1`；CMD 2 首先下发状态 `2`，设备不接受时改发状态 `3`，进入接收状态后发送 `C`。CMD 3 必须在允许擦写前确认原始长度可容纳且元数据有效，接受后回复成功并发送 `C`。

YMODEM 每包使用 CRC16，并保留超时及 NAK 重传、双 EOT 握手、结束空包确认和 CAN CAN 取消处理。Bootloader 按声明的原始长度裁剪末包填充，校验实际写入长度和完整固件 CRC32，再按本 MCU 的镜像格式确认可启动；检查失败应拒绝完成，只有全部校验成功后才发送结束空包的最终 ACK。上位机收到最终 ACK 后报告传输完成，实际启动由设备 Bootloader 决定。接收端应正确处理分段输入、重复数据包及结束 ACK 丢失后的重答。

升级库只保留自动 IAP + YMODEM 流程，固件数据包固定为 1024 字节。每次升级独立选择串口，无需实现电池或 NTC 识别协议。浏览器选中当前监测使用的同一串口时，程序自动暂停原协议，复用现有1500000 baud连接的独占通道，结束后恢复监测。

## 电池安全信息监测

监测页包含总电压、各串级电压、电池温度、电芯型号、完整编码，以及过充电压和异常温度记录，数据均从设备串口读取。“电芯信息”卡片仅显示“型号”和“编码”，不单列生产厂商和生产日期。网页目前原样展示编码，不自动解码；真实编码需配套可用的解析规则，能够解析出生产厂和生产日期。依据 GB 47372—2026 第 6.8 条区分实时监测和已存储异常信息；页面展示不代表设备已经通过标准检测。电芯编码必须来自下位机真实生产信息，不能用型号或生产日期代替。

连接后只自动读取一次异常记录，不重复查询握手得到的型号和编码，随后持续接收设备主动上报；如需重新读取，可断开后重新连接。页面不进行周期轮询，也不查询或设置设备当前时间、不改写电芯信息；异常记录的发生时间仍由下位机提供。电池监测与数字电位器共用一个物理串口，切换功能页不关闭连接，也不重复打开端口或重新读取历史。电池主动上报与温度回复由同一读循环分发，各自校验完整帧；发送按整帧排队。任一页断开会同步断开全部功能页。切换到固件升级页同样保持连接；在浏览器弹窗中选中同一串口后，升级会暂停监测与温度协议并独占收发，结束后恢复监测，重新进行电池握手并读取异常记录。选择其他串口升级时继续保留原监测连接。

连接扫描优先核验记住且唯一匹配的端口，其余已授权端口只在识别出唯一设备后连接。识别仅发送一次读型号/编码的0x08请求，等待有效响应；超时、CRC或格式错误不会作为匹配。候选端口识别后关闭，最终选中的端口重新打开并再次识别；关闭失败则保留会话，显示“重试断开”。取消或关闭网页会停止扫描，功能页切换不释放已连接设备。0x08没有随机校验值或事务序号，因此只能确认该端口支持电池协议，不能严格区分该端口迟到的旧型号回复；不把特定型号或编码写死为设备白名单。

未连接设备时，电池监测页仅显示连接按钮和必要提示，不显示最近上报、实时参数、电芯信息及异常记录。连接成功后，没有上报的字段显示 `—`。串口打开不代表已经收到设备数据。未收到异常记录时显示 `—`，已收到部分记录时显示记录及完整性提示；只有明确收到完整的零条记录才显示“无异常记录”。断开后隐藏监测数据，重新连接清空上一台设备的数据。

### 普通数据串口协议

沿用参考工程的 **1500000 baud、8 数据位、1 停止位、无校验、无流控**，浏览器接收缓存 64 KiB。

```text
AA BB | CMD U8 | LEN U16LE | PAYLOAD[LEN] | CRC8 U8
```

CRC8 初值 `0xFF`，多项式 `0x07`，按最高位优先计算，不反射、不做末尾异或。覆盖 `CMD + LEN低字节 + LEN高字节 + PAYLOAD`，不包含 `AA BB`。响应及主动上报使用相同格式，参考固件响应沿用原命令号；上位机也接受参考网页兼容的 `CMD | 0x80`。这与升级使用的 `AA 55` 帧不同。

接收器支持串口分片、粘包、噪声和 CRC 校验。以下多字节整数统一小端。当前自动发送的电池握手和历史读取请求均为空载荷，两条请求沿用参考网页 8 ms 命令间隔，无实时参数批量查询或定时轮询。

| CMD              | 上位机请求 PAYLOAD | 下位机响应 / 主动上报 PAYLOAD                         |
| ---------------- | ------------------ | ----------------------------------------------------- |
| `0x02`           | `TYPE U8`          | `TYPE U8 + VALUE`，字段见下表                         |
| `0x08`           | 空                 | `型号长度 U8 + 型号 ASCII + 编码长度 U8 + 编码 ASCII` |
| `0x0A`，本次扩展 | 空                 | 异常记录开始、单条记录、结束帧，见下文                |

`CMD 0x02` 必要参数：

| TYPE             | 字段         | VALUE 格式及单位                        | 参考固件情况                   |
| ---------------- | ------------ | --------------------------------------- | ------------------------------ |
| `0x00`           | 电池温度     | `I16LE`，0.1 ℃                          | 已有；当前固件源数据实际为整 ℃ |
| `0x01`           | 电池总电压   | `U16LE`，mV                             | 已有                           |
| `0x02`           | 第一串电压   | `U16LE`，mV                             | 已有                           |
| `0x03`           | 第二串电压   | `U16LE`，mV                             | 已有                           |
| `0x0D`           | 电池串数     | `U8`，1–16                              | 已有枚举，参考固件尚未处理     |
| `0x0F`           | 电池厂商     | ASCII，不带结尾 NUL                     | 已有                           |
| `0x10`           | 电池生产日期 | ASCII，建议 `YYYY-MM-DD`                | 已有                           |
| `0x12`，本次扩展 | 全部串级电压 | `串数 U8 + 每串电压 U16LE`，1–16 串，mV | 下位机待实现                   |

扩展的全部串级电压可用于任何 1–16 串设备。只有明确上报为 2 串及以上时，页面才显示“各串电压”卡片；串数未上报或为 1 串时隐藏卡片，电池信息铺满这一行。每一项表示一个串联级/并联块的电压。下位机不需要为不存在的串级补零；仅上报旧的第一、第二串电压不能确认串数，需配套上报 `0x0D` 串数或 `0x12` 全部串级电压。

型号和编码沿用 `0x08` 的长度前缀格式。参考固件各字段上限 24 字符，发送缓存 64 字节；上位机允许长度字节表达的 1–255 字符，以完整显示扩展后的实际编码。下位机若扩展字段长度，需相应调整存储和发送缓存，不能仅修改上位机。ASCII 内容不包含 NUL。

### 异常发生时间格式

异常记录采用的“北京时间戳”是将北京时间日历自 `1970-01-01 00:00:00` 累加得到的秒数，相当于普通 Unix UTC 秒数加 `28800`，**并非普通 Unix UTC 时间戳**。

上位机在协议层减去 `28800`，界面统一按 `Asia/Shanghai` 显示，不受电脑所在时区影响。数值 `0` 表示设备没有有效时间，显示“未记录”，不得用接收时间代替异常发生时间。

### 异常记录协议（本次扩展 CMD 0x0A）

参考工程目前没有异常记录串口命令。本次在原帧结构上增加 `0x0A`，下位机需按以下约定实现；旧固件对该命令无响应，界面保持等待状态，不解释为零条记录。

上位机发送空载荷请求设备已存储的全部异常记录，保留统一的长度字段 `LEN = 0`，请求帧为 `AA BB 0A 00 00 CRC`。型号查询同样为空载荷；历史响应格式保持不变。下位机依次发送：

1. **开始帧**：`00 + TOTAL U16LE`，总共 3 字节。
2. **记录帧**：每条异常一帧，固定 16 字节，见下表。
3. **结束帧**：`02 + TOTAL U16LE`，总共 3 字节。`TOTAL` 必须与开始帧一致，并等于本次不同记录 ID 的数量。

| 记录帧 PAYLOAD 偏移 | 长度 | 字段         | 含义                                                    |
| ------------------- | ---- | ------------ | ------------------------------------------------------- |
| 0                   | 1    | 操作         | 固定 `01`                                               |
| 1                   | 4    | ID，U32LE    | 记录唯一编号；重发、再次读取同条记录沿用原 ID           |
| 5                   | 1    | TYPE         | `0` 电池过充电压；`1` 电池/电池组异常温度               |
| 6                   | 1    | CELL         | `0` 整组（仅温度）；`1–16` 对应串联级，过充必须指明串级 |
| 7                   | 1    | STATE        | `0` 空闲；`1` 放电；`2` 充电，与参考实时状态定义一致    |
| 8                   | 4    | VALUE，I32LE | 过充电压单位 mV；异常温度单位 0.1 ℃                     |
| 12                  | 4    | TIME，U32LE  | 异常发生的北京时间计秒，`0` 为未记录                    |

新事件也可只发送记录帧，直接推送给上位机，无需先收到读取请求。上位机按 ID 去重，独立推送不会凭空证明历史记录已全部读完。完整零记录需要发送开始 `00 00 00` 和结束 `02 00 00`；不能仅保持静默。错误长度、非法字段或 CRC 错误不会作为有效记录展示。

下位机负责按标准触发、存储和保持异常记录，上位机负责读取与展示，不能只在网页连接时采集异常。过充记录每级电池充电超过上限时的电压，按 1 小时间隔保存最不利值；异常温度按标准规定的高温保护和超温条件保存每小时最高值，并保存发生时间（至少到分钟）。本次不实现下位机存储、保护或禁用逻辑。

### 联调验证

先用现有固件确认温度、总电压、前两串电压、型号/编码和厂商/日期；再按上述扩展加入串数/全部串级电压与异常历史上报。检查非零记录、明确零记录、缺失记录、重复 ID、异常发生时间、分片与连续报文、断线重连及监测到升级的切换。主机模拟测试不等同于真实串口和板上验证。
