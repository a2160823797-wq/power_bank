# PowerBank

当前异常历史按每串过充、充电高温、放电高温分别展示，按发生时间从新到旧筛选每类最多5条。设备返回全部有效记录，上位机用全部接收数量核对完整性，再筛选显示；超出的记录仅不展示，不向芯片发送擦除或清空命令。类型0～15为第1～16串过充、16为充电高温、17为放电高温；更旧记录转换要求见下文。

配套new_gb当前模拟采样为两串25℃充电，第1串4400mV、第2串4000mV，`overcharge_mask=0x01`仅标记第1串过充，第2串正常，不触发高温。总压3968mV保持用户原值；总压与各串电压为独立模拟输入，不自动求和。收到两串上报后，页面显示两项串级电压。

现已新增 **数字电位器 / NTC 模拟器** 页面，搭配 `C:/Desktop/new_gb` 的 STM32F103C8T6 + AD5270 固件，监测与温度控制串口使用1500000 baud。当前仅实现串口连接和温度滑条设置，保留原电池监测与升级页面。连接后拖动−25～125℃滑条只更新显示，松开后下发温度命令并等待CRC正确的STM32回复，超时或设备返回失败时提示用户；未收到回复前保留最新已提交温度，不并发发送。暂不实现自动温度扫描、测试记录和CSV导出。完整厂家表、架构、协议与硬件说明见 [NTC模拟器文档](../new_gb/docs/NTC_SIMULATOR.md)。

数字电位器页点击“连接设备”后扫描浏览器已授权的端口，通过只读 `AA 02 / AA 82` 握手确认 NTC 模拟器，再用 `AA BB 08 00 00 CRC` 读取同一设备的电池型号和编码，供共用连接的电池监测页显示。优先尝试此前记住且唯一匹配的设备；其余端口只有识别到唯一设备时才连接。未找到或找到多台时，同一按钮改为“选择设备”，再次点击打开浏览器授权窗口，选择后仍需通过识别。扫描不发送温度设置，也不改变AD5270输出。没有已授权端口时，首次点击直接进入浏览器选择窗口。配套STM32必须先烧录支持识别命令的新固件，普通USB串口适配器的VID/PID不能证明下位机型号。

电池监测页同样先扫描已授权端口，用现有 `AA BB 08 00 00 CRC` 查询型号和编码。CRC、长度及非空ASCII内容全部正确后才确认支持电池监测；多个匹配时选择设备，手动选择后也需识别。识别期间不读取异常历史、不改写电池信息，也不把候选端口的数据展示到页面。连接成功后保留握手得到的型号和编码，只自动读取异常记录，实时温度、总压及各串电压由下位机每100 ms主动上报。这次电池识别无需新增固件命令。

运行 `npm run test:ntc` 和 `npm run test:ntc-connection` 验证温度协议与设备识别连接，`npm run build:offline` 更新单文件 `PowerBank.html`。本次未烧录或验证真实AD5270输出。

串口上位机提供电池安全信息监测、异常记录读取和通用 MCU 固件升级。电池监测继续适配 `x202_015`；升级统一使用 IAP + YMODEM 自动进入升级，各 MCU 的配套固件按同一协议接入，上位机不区分芯片型号。电池监测参考 `C:/Desktop/index.html` 以及 `C:/Desktop/prj/x202/firmware/x202_015/System/cmd.c`、`System/uart.c`。

## 使用

页面统一使用中文，电池监测、数字电位器、异常记录与固件升级均显示中文文案。

1. 使用桌面版 Chrome 或 Edge，连接 USB 转串口和目标设备。
2. 双击 `PowerBank.html` 打开页面。运行现成页面无需安装 Node.js 或启动本地服务。
   首次授权需手动选择设备；连接成功后会记住设备标识，下次打开自动尝试连接。使用同一浏览器并保持网页路径不变，才能复用此前授权和本地记录。两页共用一份设备记忆，刷新或再次打开时校验并自动连接此前记住的设备。
3. 页面记住最后打开的功能，首次默认进入“电池监测”。点击“连接设备”接收下位机上报；升级时切换到“固件升级”，选择目标设备对应的 APP `.bin` 固件，点击“一键升级”。用户无需选择芯片型号或填写升级参数。
4. 点击“一键升级”后自动扫描已授权串口，用只读 IAP CMD 0 确认设备在线；优先尝试当前监测连接或上次升级设备，其余端口只有唯一匹配时才升级。没有已授权端口时直接打开浏览器授权窗口；未找到或找到多台设备时，按提示再次点击“一键升级”选择目标设备，选择后也会先确认 IAP 在线。按钮只保留文字。
5. 等待自动升级完成；完成后进度条变绿，需要再次升级时点击文件区域重新选择固件。

升级过程中只显示文件名和进度条，失败时显示错误提示并可展开查看详情。升级要求目标 MCU 使用支持本工程 CMD 0/2/3 和 YMODEM 的配套固件；芯片型号本身不能保证协议兼容，厂家 ROM ISP 协议需要另行适配。升级期间锁定固件选择。

## 开发与验证

本工程只包含上位机。所有升级固定使用 IAP + YMODEM、1500000 baud、8N1 和 1K（1024 字节）固件数据包。用户页面仅保留固件选择、一键升级和进度条，失败时显示错误提示和可展开详情，不展示连接方式、型号、内存地址、容量、协议、串口参数、超时或重试配置。`DEFAULT_CONFIG` 只包含统一传输参数：5000 ms 响应超时、30000 ms 握手超时、最多尝试10次。型号偏好存储已删除，旧浏览器记录中的型号和自定义参数不再读取。

上位机仅检查文件非空和原始固件长度可由 32 位字段表达，将 BIN 作为原始字节传输。应用写入地址、Flash/RAM 容量、CPU 架构、镜像合法性和启动条件均由各 MCU 的 Bootloader 判断；Cortex-M 设备在设备端检查向量表，其他架构按自身启动格式检查。新增 MCU 只需实现下述固件协议，无需在上位机新增型号或内存配置。用户仍需选择目标产品对应的固件，当前长度和 CRC32 信息不包含产品型号，上位机无法据此判断固件是否属于该产品。

参考工程 `x202_015` 的当前 CS32L015 Bootloader 支持同一命令协议和 STX 1024 字节接收，UART 缓冲为 1030 字节。设备在 CMD 3 阶段拒绝过小或超应用区容量的长度，写入完成后检查实际长度、CRC32 和向量表并决定是否允许启动；上位机不再保存这颗芯片的 APP/RAM 参数。删除主机向量表检查后，非法向量固件由设备在写入完成时拒绝，此时原 APP 已擦除。统一响应超时保持 5000 ms，以便在该工程 7000 ms 最终 ACK 重答窗口内重试。

当前参考工程 `C:/Desktop/prj/hand_fan/hand_fan_910/iap/src/xymodem.c` 的 CW32L910 接收缓冲只容纳 128 字节数据包，且 `xymodem_read()` 收到 STX 会发 CAN 拒绝，因此这版 Bootloader 仍需更新为支持 1K 才能接入统一上位机。本次未修改任何 MCU 工程。

### IAP 升级流程

1. 检查 BIN 非空和长度范围；校验失败即停止升级。
2. CMD 0 确认设备在线。
3. CMD 2 自动进入升级状态，等待设备发出 `C`。
4. CMD 3 发送原始固件长度和 CRC32，等待设备接受。
5. 发送 YMODEM 文件头、固定 1K 数据包、EOT 和结束空包，收到最终 ACK 后报告传输成功。EOT 收到 NAK 时再次发送，收到 ACK 后等待 `C` 并发送结束空包。文件头和结束空包使用 SOH + 128 字节，固件数据包使用 STX + 1024 字节；末包用 `0x1A` 补齐，原始固件长度和 CRC32 不包含填充。

命令帧格式为 `AA 55 | CMD[1] | LEN[2] | DATA[LEN] | CRC8[1]`，长度为小端 uint16。CRC8 覆盖命令、长度和数据，初值 `0xFF`，多项式 `0x07`。CMD 3 数据为原始固件长度 LE32 和 CRC32 LE32。

YMODEM 包格式为 `SOH/STX | 包序号 | 序号按位取反 | 数据 | CRC16高字节 | CRC16低字节`，数据包序号从 `1` 开始，按 8 位回绕。CRC16 覆盖整包数据区，包括末包填充，初值 `0`，多项式 `0x1021`。文件头序号为 `0`，128 字节数据区包含 ASCII 文件名、零分隔符、十进制原始文件长度和零终止符。结束空包同样为序号 `0` 的 SOH 包，128 字节数据区全零。

CMD 3 的 CRC32 只覆盖原始固件，使用反射多项式 `0xEDB88320`，初值和最终异或均为 `0xFFFFFFFF`；以小端 32 位值发送。设备应将文件头中的长度与 CMD 3 的长度核对，实际写入末包时裁掉填充。

运行中的 APP 必须支持 CMD 0 在线确认和 CMD 2 进入升级状态；Bootloader 必须支持 CMD 0、CMD 2、CMD 3 及 YMODEM 1K 接收。仅实现 YMODEM 接收器不足以自动进入升级。在线和命令接受回复首个数据字节为 `1`；CMD 2 首先下发状态 `2`，设备不接受时改发状态 `3`，进入接收状态后发送 `C`。CMD 3 必须在允许擦写前确认原始长度可容纳且元数据有效，接受后回复成功并发送 `C`。

YMODEM 每包使用 CRC16，并保留超时及 NAK 重传、双 EOT 握手、结束空包确认和 CAN CAN 取消处理。Bootloader 按声明的原始长度裁剪末包填充，校验实际写入长度和完整固件 CRC32，再按本 MCU 的镜像格式确认可启动；检查失败应拒绝完成，只有全部校验成功后才发送结束空包的最终 ACK。上位机收到最终 ACK 后报告传输完成，实际启动由设备 Bootloader 决定。接收端应正确处理分段输入、重复数据包及结束 ACK 丢失后的重答。

升级库只保留自动 IAP + YMODEM 流程，固件数据包固定为 1024 字节。升级扫描不要求电池或 NTC 识别协议，只发送 CMD 0 并等待最多500 ms；合法 CRC、CMD 0 和成功响应首字节 `1` 全部满足才作为匹配，不发送进入升级、固件元数据或取消命令。扫描到当前监测串口时通过虚拟通道识别，实际升级再暂停原协议，复用现有1500000 baud连接的独占通道，结束后恢复监测。其他串口探测后先关闭，升级时重新打开并确认在线。

## 电池安全信息监测

监测页包含总电压、各串级电压、电池温度、电芯型号、完整编码，以及过充电压和异常温度记录，数据均从设备串口读取。实时温度和异常温度统一按 1℃ 单位传输和显示，数值 `65` 表示 `65℃`。本版本需与配套固件同步更新。“电芯信息”卡片仅显示“型号”和“编码”，不单列生产厂商和生产日期。网页目前原样展示编码，不自动解码；真实编码需配套可用的解析规则，能够解析出生产厂和生产日期。依据 GB 47372—2026 第 6.8 条区分实时监测和已存储异常信息；页面展示不代表设备已经通过标准检测。电芯编码必须来自下位机真实生产信息，不能用型号或生产日期代替。

连接后只自动读取一次异常记录，不重复查询握手得到的型号和编码，随后持续接收设备主动上报；如需重新读取，可断开后重新连接。页面不进行周期轮询，也不查询或设置设备当前时间、不改写电芯信息；异常记录的发生时间仍由下位机提供。电池监测与数字电位器共用一个物理串口，切换功能页不关闭连接，也不重复打开端口或重新读取历史。电池主动上报与温度回复由同一读循环分发，各自校验完整帧；发送按整帧排队。任一页断开会同步断开全部功能页。切换到固件升级页同样保持连接；点击“一键升级”自动确认同一串口支持 IAP 后，升级会暂停监测与温度协议并独占收发，结束后恢复监测，重新进行电池握手并读取异常记录。选择其他串口升级时继续保留原监测连接。

连接扫描优先核验记住且唯一匹配的端口，其余已授权端口只在识别出唯一设备后连接。识别仅发送一次读型号/编码的0x08请求，等待有效响应；超时、CRC或格式错误不会作为匹配。候选端口识别后关闭，最终选中的端口重新打开并再次识别；关闭失败则保留会话，显示“重试断开”。取消或关闭网页会停止扫描，功能页切换不释放已连接设备。0x08没有随机校验值或事务序号，因此只能确认该端口支持电池协议，不能严格区分该端口迟到的旧型号回复；不把特定型号或编码写死为设备白名单。

未连接设备时，电池监测页仅显示连接按钮和必要提示，不显示最近上报、实时参数、电芯信息及异常记录。连接成功后，没有上报的字段显示 `—`。串口打开不代表已经收到设备数据。未收到异常记录时显示 `—`，已收到部分记录时显示记录及完整性提示；只有明确收到完整的零条记录才显示“无异常记录”。断开后隐藏监测数据，重新连接清空上一台设备的数据。

异常记录按每一串过充、充电高温、放电高温分别取发生时间最新的5条，再按时间从新到旧展示，只展示实际有历史的分类。按串数计算的理论展示上限为 `5 × (串数 + 2)`，两串电池加两类高温共4类、最多20条，16串最多90条；每类不足5条时显示实际数量。筛选仅作用于网页显示，不改变已接收的全量记录和完整性计数，不擦除芯片历史或旧峰值物理槽。参考x202的每类5条只是展示规则，不是标准规定的记录上限。

### 普通数据串口协议

沿用参考工程的 **1500000 baud、8 数据位、1 停止位、无校验、无流控**，浏览器接收缓存 64 KiB。

```text
AA BB | CMD U8 | LEN U16LE | PAYLOAD[LEN] | CRC8 U8
```

CRC8 初值 `0xFF`，多项式 `0x07`，按最高位优先计算，不反射、不做末尾异或。覆盖 `CMD + LEN低字节 + LEN高字节 + PAYLOAD`，不包含 `AA BB`。响应及主动上报使用相同格式，参考固件响应沿用原命令号；上位机也接受参考网页兼容的 `CMD | 0x80`。这与升级使用的 `AA 55` 帧不同。

接收器支持串口分片、粘包、噪声和 CRC 校验。以下多字节整数统一小端。当前自动发送的电池握手和历史读取请求均为空载荷，两条请求沿用参考网页 8 ms 命令间隔，无实时参数批量查询或定时轮询。

| CMD              | 上位机请求 PAYLOAD | 下位机响应 / 主动上报 PAYLOAD                         |
| ---------------- | ------------------ | ----------------------------------------------------- |
| `0x02`           | `TYPE U8`          | `TYPE U8 + VALUE`，字段见下表                         |
| `0x08`           | 空                 | `型号长度 U8 + 型号 ASCII + 编码长度 U8 + 编码 ASCII` |
| `0x0A`，本次扩展 | 空                 | 异常记录开始、单条记录、结束帧，见下文                |

`CMD 0x02` 必要参数：

| TYPE             | 字段         | VALUE 格式及单位                        | 参考固件情况                   |
| ---------------- | ------------ | --------------------------------------- | ------------------------------ |
| `0x00`           | 电池温度     | `I16LE`，1 ℃                            | 已有；与配套固件同步更新       |
| `0x01`           | 电池总电压   | `U16LE`，mV                             | 已有                           |
| `0x02`           | 第一串电压   | `U16LE`，mV                             | 已有                           |
| `0x03`           | 第二串电压   | `U16LE`，mV                             | 已有                           |
| `0x0D`           | 电池串数     | `U8`，1–16                              | 已有枚举，参考固件尚未处理     |
| `0x0F`           | 电池厂商     | ASCII，不带结尾 NUL                     | 已有                           |
| `0x10`           | 电池生产日期 | ASCII，建议 `YYYY-MM-DD`                | 已有                           |
| `0x12`，本次扩展 | 全部串级电压 | `串数 U8 + 每串电压 U16LE`，1–16 串，mV | 下位机待实现                   |

扩展的全部串级电压可用于任何 1–16 串设备。连接后串数未上报时，页面默认显示两项串级电压，不显示“各串电压”标题和串数提示；收到 `0x0D` 串数或 `0x12` 全部串级电压后按实际串数显示，为 1 串时隐藏卡片，电池信息铺满这一行。每一项表示一个串联级/并联块的电压。下位机不需要为不存在的串级补零；仅上报旧的第一、第二串电压时沿用两串默认显示。

型号和编码沿用 `0x08` 的长度前缀格式。参考固件各字段上限 24 字符，发送缓存 64 字节；上位机允许长度字节表达的 1–255 字符，以完整显示扩展后的实际编码。下位机若扩展字段长度，需相应调整存储和发送缓存，不能仅修改上位机。ASCII 内容不包含 NUL。

### 异常发生时间格式

异常记录采用的“北京时间戳”是将北京时间日历自 `1970-01-01 00:00:00` 累加得到的秒数，相当于普通 Unix UTC 秒数加 `28800`，**并非普通 Unix UTC 时间戳**。

上位机在协议层减去 `28800`，界面统一按 `Asia/Shanghai` 显示，不受电脑所在时区影响。所有记录均使用设备提供的发生时间，不再定义“时间未知”状态；协议数值 `0` 按北京时间 `1970-01-01 00:00:00` 显示，不用接收时间代替异常发生时间。

### 异常记录协议（本次扩展 CMD 0x0A）

参考工程目前没有异常记录串口命令。本次在原帧结构上增加 `0x0A`，下位机需按以下约定实现；旧固件对该命令无响应，界面保持等待状态，不解释为零条记录。

上位机发送空载荷请求设备已存储的全部异常记录，保留统一的长度字段 `LEN = 0`，请求帧为 `AA BB 0A 00 00 CRC`。型号查询同样为空载荷；异常记录仅包含类型、数值和时间。下位机依次发送：

1. **开始帧**：`00 + TOTAL U16LE`，总共 3 字节。
2. **记录帧**：每条异常一帧，固定 8 字节，见下表。
3. **结束帧**：`02 + TOTAL U16LE`，总共 3 字节。`TOTAL` 必须与开始帧一致，并等于本次有效记录帧的数量。

| 记录帧 PAYLOAD 偏移 | 长度 | 字段         | 含义                                      |
| ------------------- | ---- | ------------ | ----------------------------------------- |
| 0                   | 1    | 操作         | 固定 `01`                                 |
| 1                   | 1    | TYPE         | `0～15` 第1～16串过充电压；`16` 充电高温；`17` 放电高温 |
| 2                   | 2    | VALUE，I16LE | 过充电压单位 mV；异常温度单位 1 ℃         |
| 4                   | 4    | TIME，U32LE  | 异常发生的北京时间计秒                    |

异常数值使用有符号 16 位整数，范围为 `-32768～32767`；每串过充电压只接受非负值，可表示到 `32767 mV`。串级及充电、放电高温分类直接由TYPE表达，不增加独立串号或状态字段。类型0～17编码及含义不变，可以继续读取此前每串过充及充放电高温记录。旧版10字节记录帧不再接受；更旧8字节记录帧虽长度相同，但TYPE的0/1原先表示汇总过充/高温，当前表示第1/2串过充，不能按当前分类安全重解释。固件与离线网页 `PowerBank.html` 应同时更新；开始/结束帧、北京时间秒数换算以及外层 CRC8 规则不变。

开始帧清空上一份网页历史快照，上位机按收到的顺序追加全部记录。下位机负责返回每条异常的当前有效记录，同一类型和时间可对应多条异常，上位机不按这两个字段去重。TOTAL按全部有效记录帧数量核对，不能改为每类5条筛选后的展示数量。单独收到记录帧会显示该记录并标记历史不完整。完整零记录需要发送开始 `00 00 00` 和结束 `02 00 00`；不能仅保持静默。错误长度、非法字段或CRC错误不会作为有效记录展示，也不会报告历史已完整读取。页面显示第几串过充、充电高温或放电高温，以及数值和发生时间，不显示记录ID。

下位机负责按标准触发、存储和保持异常记录，上位机负责读取与展示，不能只在网页连接时采集异常。[GB 47372—2026官方正文](https://js.119.gov.cn/group1/M00/00/10/Ci6RgmnUZmWAGZJTACo1u3fmVhI881.pdf)第6.8条规定按每一级电池记录过充电压，按1小时间隔保存最不利值；异常温度满足记录条件时每小时至少记录一次，保存最高值和发生时间。标准未规定异常记录最多多少条，保存期限为宜不少于建议安全使用年限。配套new_gb固件分别保存各串过充、充电高温和放电高温的同一UTC小时峰值及其发生时间，首次异常即时保存、更高峰值按分钟或异常退出/小时切换追加；用户确定的高温门限为充电≥50℃、放电≥60℃，空闲不记录。本上位机不实现设备端采集、保护或禁用逻辑。

配套new_gb的Flash仍为8字节槽、1024个物理槽。此前类型0～17的各串过充及充放电高温记录可以继续读取和追加，无需转换或清空。更旧的类型0/1记录没有保存独立串级和高温充放电分类，不能自动还原这些信息；切换前应使用旧固件及对应网页导出，确认归属后离线迁移，或仅清空 `0x0800E000～0x0800FFFF` 历史区。串口升级及网页显示筛选都不会自动迁移或清空历史。当前软件修改没有操作板上记录。
