# PowerBank

适配 `x202_015` 的串口上位机，提供电池安全信息监测、异常记录读取和固件升级。页面已内置串口与升级参数，无需配置。电池监测参考 `C:/Desktop/index.html` 以及 `C:/Desktop/prj/x202/firmware/x202_015/System/cmd.c`、`System/uart.c`。

## 使用

页面首次打开默认英文，可使用页头右侧的 `EN / 中文` 切换界面语言；之后会记住选择。语言切换同时适用于电池监测、异常记录和固件升级提示，不重新连接串口，也不清空已接收的数据。

1. 使用桌面版 Chrome 或 Edge，连接 USB 转串口和目标设备。
2. 双击 `PowerBank.html` 打开页面。运行现成页面无需安装 Node.js 或启动本地服务。
   首次连接需手动选择串口；连接成功后会记住设备标识，下次打开自动尝试连接已授权且唯一匹配的端口。端口不可用、授权失效或多个同型号端口无法区分时，请手动选择。使用同一浏览器并保持网页路径不变，才能复用此前授权和本地记录。切换功能页不会再次自动连接。
3. 页面默认进入“电池监测”，点击“连接设备”接收下位机上报；升级时切换到“固件升级”，选择对应设备的 APP `.bin` 固件，点击“一键升级”。
4. 在浏览器弹出的串口选择窗口中，选择目标设备并连接；浏览器要求此步骤由用户完成，上位机不会自动选择串口。
5. 等待自动升级完成；需要中止时点击“取消”。

升级过程中显示当前状态和传输进度，失败时可展开查看详情。页面适用于上述设备工程，其他设备需由开发者完成适配后再分发。

## 开发与验证

本工程只包含上位机。页面直接使用 `DEFAULT_CONFIG`，固定适配 `x202_015` Bootloader：IAP + Ymodem、1500000 baud、8N1、128 字节数据包、5000 ms 响应超时；APP 起始地址 `0x4800`、容量 `0xB400`（45 KiB），SRAM 起始地址 `0x20000000`、容量 `0x2000`（8 KiB）。传输前自动检查文件大小和 Cortex-M 向量表，页面不提供参数设置入口。

### IAP 升级流程

1. 按内置配置检查 BIN 大小和向量表；校验失败即停止升级。
2. CMD 0 在线确认。
3. CMD 2 进入升级状态，等待设备发出 Ymodem CRC 请求 `C`。
4. CMD 3 发送原始固件长度和 CRC32，等待设备接受。
5. 发送 Ymodem 文件头、数据包、双 EOT 和结束空包，收到最终 ACK 后报告传输成功。

命令帧格式为 `AA 55 | CMD[1] | LEN[2] | DATA[LEN] | CRC8[1]`，长度为小端 uint16。CRC8 覆盖命令、长度和数据，初值 `0xFF`，多项式 `0x07`。CMD 3 数据为原始固件长度 LE32 和 CRC32 LE32。

IAP 模式要求目标 Bootloader 实现 CMD 0/2/3 并允许直接接收固件。`x202_015` 必须先收到 CMD 3 的固件长度和 CRC32，页面固定使用 IAP + Ymodem。Ymodem 保留 CRC16 校验、超时及 NAK 重传、双 EOT 握手、结束空包确认和取消处理。传输成功表示接收端已确认完成，固件擦写校验和启动行为由设备 Bootloader 决定。

协议库仍保留标准 Ymodem 和 128/1024 字节数据包能力，用于开发适配与回归；标准 Ymodem 直接等待接收端请求，不发送 IAP 命令，不能直接用于当前 `x202_015` 升级流程。

开发环境需要 Node.js 22.13 或以上版本：

```powershell
npm install
npm run test:iap
npm run test:battery
npx tsc --noEmit

```

`test:iap` 使用模拟串口验证命令握手、固件校验、数据包传输、重试、取消和结束确认。`build:offline` 生成可单独分发的 `PowerBank.html`，双击即可打开。

`X202_CONFIG` 对应当前 `x202_015` 分区，`CW32L910_CONFIG` 保留既有内存配置用于兼容性回归，不能直接套用到其他 MCU。主机测试不能替代实机串口、Flash 擦写、固件启动和断电验证。

## 电池安全信息监测

监测页包含总电压、各串级电压、电池温度、电芯型号、完整编码，以及过充电压和异常温度记录，数据均从设备串口读取。“电芯信息”卡片仅显示“型号”和“编码”，不单列生产厂商和生产日期。网页目前原样展示编码，不自动解码；真实编码需配套可用的解析规则，能够解析出生产厂和生产日期。依据 GB 47372—2026 第 6.8 条区分实时监测和已存储异常信息；页面展示不代表设备已经通过标准检测。电芯编码必须来自下位机真实生产信息，不能用型号或生产日期代替。

连接后自动读取一次必要信息及异常记录，随后持续接收设备主动上报；如需重新读取，可断开后重新连接。页面不进行周期轮询，也不自动设置时间或改写电芯信息。切换到固件升级前会关闭监测连接，升级期间不能切换监测，避免两个协议共用串口时相互干扰。

没有上报的字段显示 `—`。串口打开不代表已经收到设备数据。未收到异常记录时显示 `—`，已收到部分记录时显示记录及完整性提示；只有明确收到完整的零条记录才显示“无异常记录”。断开后保留最后接收数据显示，重新连接清空上一台设备的数据。

### 普通数据串口协议

沿用参考工程的 **1500000 baud、8 数据位、1 停止位、无校验、无流控**，浏览器接收缓存 64 KiB。

```text
AA BB | CMD U8 | LEN U16LE | PAYLOAD[LEN] | CRC8 U8
```

CRC8 初值 `0xFF`，多项式 `0x07`，按最高位优先计算，不反射、不做末尾异或。覆盖 `CMD + LEN低字节 + LEN高字节 + PAYLOAD`，不包含 `AA BB`。响应及主动上报使用相同格式，参考固件响应沿用原命令号；上位机也接受参考网页兼容的 `CMD | 0x80`。这与升级使用的 `AA 55` 帧不同。

接收器支持串口分片、粘包、噪声和 CRC 校验。以下多字节整数统一小端。读取请求最多 32 字节，当前各请求均不超过 1 字节。批量读取沿用参考网页 8 ms 命令间隔，无定时轮询。

| CMD              | 上位机请求 PAYLOAD | 下位机响应 / 主动上报 PAYLOAD                         |
| ---------------- | ------------------ | ----------------------------------------------------- |
| `0x02`           | `TYPE U8`          | `TYPE U8 + VALUE`，字段见下表                         |
| `0x03`           | `01`               | 4 字节北京时间计秒；也可接收参考协议的 8 字节日历格式 |
| `0x08`           | 空                 | `型号长度 U8 + 型号 ASCII + 编码长度 U8 + 编码 ASCII` |
| `0x0A`，本次扩展 | `00`               | 异常记录开始、单条记录、结束帧，见下文                |

`CMD 0x02` 必要参数：

| TYPE             | 字段         | VALUE 格式及单位                        | 参考固件情况                   |
| ---------------- | ------------ | --------------------------------------- | ------------------------------ |
| `0x00`           | 电池温度     | `I16LE`，0.1 ℃                          | 已有；当前固件源数据实际为整 ℃ |
| `0x01`           | 电池总电压   | `U16LE`，mV                             | 已有                           |
| `0x02`           | 第一串电压   | `U16LE`，mV                             | 已有                           |
| `0x03`           | 第二串电压   | `U16LE`，mV                             | 已有                           |
| `0x0D`           | 电池串数     | `U8`，1–16                              | 已有枚举，参考固件尚未处理     |
| `0x0F`           | 电池厂商     | ASCII，不带结尾 NUL                     | 已有                           |
| `0x10`           | 电池生产日期 | ASCII，建议 `YYYY-MM-DD`                | 已有                           |
| `0x12`，本次扩展 | 全部串级电压 | `串数 U8 + 每串电压 U16LE`，1–16 串，mV | 下位机待实现                   |

扩展的全部串级电压可用于任何 1–16 串设备。只有明确上报为 2 串及以上时，页面才显示“各串电压”卡片；串数未上报或为 1 串时隐藏卡片，电池信息铺满这一行。每一项表示一个串联级/并联块的电压。下位机不需要为不存在的串级补零；仅上报旧的第一、第二串电压不能确认串数，需配套上报 `0x0D` 串数或 `0x12` 全部串级电压。

型号和编码沿用 `0x08` 的长度前缀格式。参考固件各字段上限 24 字符，发送缓存 64 字节；上位机允许长度字节表达的 1–255 字符，以完整显示扩展后的实际编码。下位机若扩展字段长度，需相应调整存储和发送缓存，不能仅修改上位机。ASCII 内容不包含 NUL。

### 时间格式

参考固件的“北京时间戳”是将北京时间日历自 `1970-01-01 00:00:00` 累加得到的秒数，相当于普通 Unix UTC 秒数加 `28800`，**并非普通 Unix UTC 时间戳**。`0x03` 的 4 字节响应不带格式字节；8 字节响应为 `年 U16LE、月 U8、日 U8、星期 U8、时 U8、分 U8、秒 U8`，同样不带格式字节。

异常记录时间也采用该北京时间计秒格式。上位机在协议层减去 `28800`，界面统一按 `Asia/Shanghai` 显示，不受电脑所在时区影响。数值 `0` 表示设备没有有效时间，显示“未记录”，不得用接收时间代替异常发生时间。

### 异常记录协议（本次扩展 CMD 0x0A）

参考工程目前没有异常记录串口命令。本次在原帧结构上增加 `0x0A`，下位机需按以下约定实现；旧固件对该命令无响应，界面保持等待状态，不解释为零条记录。

上位机发送 `PAYLOAD = 00` 请求设备已存储的全部异常记录。下位机依次发送：

1. **开始帧**：`00 + TOTAL U16LE`，总共 3 字节。
2. **记录帧**：每条异常一帧，固定 16 字节，见下表。
3. **结束帧**：`02 + TOTAL U16LE`，总共 3 字节。`TOTAL` 必须与开始帧一致，并等于本次不同记录 ID 的数量。

| 记录帧 PAYLOAD 偏移 | 长度 | 字段         | 含义                                                    |
| ------------------- | ---- | ------------ | ------------------------------------------------------- |
| 0                   | 1    | 操作         | 固定 `01`                                               |
| 1                   | 4    | ID，U32LE    | 记录唯一编号；重发、再次读取同条记录沿用原 ID           |
| 5                   | 1    | TYPE         | `0` 电池过充电压；`1` 电池/电池组异常温度               |
| 6                   | 1    | CELL         | `0` 整组（仅温度）；`1–16` 对应串联级，过充必须指明串级 |
| 7                   | 1    | STATE        | `0` 空闲；`1` 放电；`2` 充电，与参考实时状态定义一致    |
| 8                   | 4    | VALUE，I32LE | 过充电压单位 mV；异常温度单位 0.1 ℃                     |
| 12                  | 4    | TIME，U32LE  | 异常发生的北京时间计秒，`0` 为未记录                    |

新事件也可只发送记录帧，直接推送给上位机，无需先收到读取请求。上位机按 ID 去重，独立推送不会凭空证明历史记录已全部读完。完整零记录需要发送开始 `00 00 00` 和结束 `02 00 00`；不能仅保持静默。错误长度、非法字段或 CRC 错误不会作为有效记录展示。

下位机负责按标准触发、存储和保持异常记录，上位机负责读取与展示，不能只在网页连接时采集异常。过充记录每级电池充电超过上限时的电压，按 1 小时间隔保存最不利值；异常温度按标准规定的高温保护和超温条件保存每小时最高值，并保存发生时间（至少到分钟）。本次不实现下位机存储、保护或禁用逻辑。

### 联调验证

先用现有固件确认温度、总电压、前两串电压、型号/编码、厂商/日期和 RTC；再按上述扩展加入串数/全部串级电压与异常历史上报。检查非零记录、明确零记录、缺失记录、重复 ID、分片与连续报文、断线重连及监测到升级的切换。主机模拟测试不等同于真实串口和板上验证。
